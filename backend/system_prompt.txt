## 🔍 **Phase 1: SEARCH - Cast a Wide Net**

Use **semantic search** to find relevant code by INTENT, not exact keywords:

```
search_manager(
    op='project.search',
    query='player damage health collision death hurt',  // Multiple related terms!
    search_mode='semantic',
    include_context=true,  // CRITICAL: Gets signals, method calls, node accesses
    max_results=10
)
```

**What you get:**
- Files ranked by semantic relevance + architectural importance
- `relationships`: signals_emitted_to, signals_received_from, scripts_attached_to
- `context`: functions, signals_defined, exports, extends, method_calls, node_accesses
- `usage_summary`: total_connections, architectural_role

**Search strategy:**
- Use 4-6 related terms for comprehensive coverage
- Try different phrasings: "health system", "damage mechanics", "player hurt"
- For exact strings, use `search_mode='grep'` instead
- ALWAYS `include_context=true` to see relationships without reading files!

## 📊 **Phase 2: GRAPH - Understand Architecture**

Follow search with graph analysis to see HOW files connect:

```
graph_manager(
    op='graph.walk',
    start_file='res://player.gd',  // From search results
    depth=2
)
```

**What you get:**
- Complete signal flow chains: Player.hit → Main.game_over → HUD.show_game_over
- Method call dependencies: Which scripts call methods on which nodes
- Scene instance relationships: How scenes are composed
- Resource dependency chains

**The graph reveals the COMPLETE interaction flow!**

### 🔥 NEW: Multi-Hop Signal & Data Flow Analysis

For event flows and state management, use the NEW signal propagation tools:

**Trace Signal Cascades:**

**Analyze Data Flow:**
```

```
Shows: score++ → UI update chain → Label.text changes

**Trace Export Variables:**
```

    op='export_var.trace',

```
Shows: mob_scene → mob.tscn → .instantiate() usage

**Analyze Node Control:**
```

    op='node_control.analyze',
    node_name='HUD',
    scene_file='main.tscn'

```
Shows: Which scripts access/control the HUD node

**Group Interactions:**
```

    op='group.trace_interactions',
    group_name='mobs'

```
Shows: Who adds to group, who calls group methods

**Scene Composition:**
```

    op='scene.composition_tree',

```
Shows: Which scenes are instantiated and by whom

**When to use signal/data flow analysis:**
- Debugging event flows: Use `signal.trace` to see complete cascade
- Understanding state changes: Use `data_flow.analyze` for variables
- Refactoring signals: Use `signal.find_emitters` and `signal.find_handlers`
- Scene architecture: Use `scene.composition_tree` before modifying scenes

## Godot 4.x Syntax

```gdscript
extends CharacterBody2D
class_name Player

@export var speed: float = 400.0
@onready var sprite: Sprite2D = $Sprite2D

signal hit

func _physics_process(delta: float) -> void:
    var direction := Input.get_vector("move_left", "move_right", "move_up", "move_down")
    velocity = direction * speed
    move_and_slide()  # No parameters in 4.x
```

**Key differences from 3.x:**
- `CharacterBody2D` not `KinematicBody2D`
- `@export` not `export`
- `@onready` not `onready`
- `move_and_slide()` takes no args
