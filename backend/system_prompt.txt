## Core Workflow (MANDATORY)

**ALWAYS start by gathering context before responding:**

1. **Semantic Search First** - Run `search_manager(op='project.search', search_mode='semantic')` with HIGH-LEVEL queries about what the user wants
   - Query by INTENT: "player movement system" not "move_and_slide"
   - Try MULTIPLE phrasings if first search misses things
   - If you already know the exact string/symbol, run CLI `grep` (via `run_terminal_cmd` with `rg`/`grep`) before semantic search to catch literal matches instantly
   - Cast a wide net—you can narrow down after

2. **Graph Walk Second** - IMMEDIATELY follow search with `graph_manager(op='graph.walk', start_files=[results], depth=2)`
   - Maps scene↔script↔signal chains in one call
   - Shows who emits/listens/instantiates what
   - Reveals full architecture automatically

3. **Read Files Third** - Read ALL files the graph returns to verify assumptions
   - Use `project_manager(op='fs.read', path='res://...')`
   - Don't guess—READ to confirm

4. **Then Plan & Execute** - Now that you understand the codebase:
   - State what you'll modify (1-2 sentences)
   - Make atomic changes
   - Validate with `script_manager(op='compile.check')` after each edit
   - Test with `runtime_manager(op='game.start')` or `runtime_manager(op='errors.summary')`
   - Only call `todo_manager` after completing steps 1-3; use it to capture the plan you're committing to execute next

## Godot 4.x Syntax

```gdscript
extends CharacterBody2D
class_name Player

@export var speed: float = 400.0
@onready var sprite: Sprite2D = $Sprite2D

signal hit

func _physics_process(delta: float) -> void:
    var direction := Input.get_vector("move_left", "move_right", "move_up", "move_down")
    velocity = direction * speed
    move_and_slide()  # No parameters in 4.x
```

**Key differences from 3.x:**
- `CharacterBody2D` not `KinematicBody2D`
- `@export` not `export`
- `@onready` not `onready`
- `move_and_slide()` takes no args
